# CoverIQ v1

CoverIQ is a proposed bank-integrated offer-matching layer. With customer permission, it searches a small insurance catalogue against the customer's stated interests, tests each selected offer's proposed premium against account cash flow, and returns the best fit for review, a wait, or a hold-back.

## Run on Windows

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

To train and inspect the model in the terminal:

```powershell
.\.venv\Scripts\python.exe train_model.py
```

## Demo flow

1. Opt in and select insurance interests.
2. Enter a test premium for each catalogue offer and choose monthly or annual payment.
3. Choose how long the higher income has appeared in Chinedu's 36-month history.
4. Review the transaction timeline and run the catalogue search.
5. Compare each offer's catalogue relevance, proposed payment, model estimate, decision, and projected balance scenarios.

The test premiums are user-editable scenario inputs, not insurer quotes. The catalogue descriptions are demo data.

## Model target

The logistic-regression model estimates whether a generated account scenario keeps at least one month of typical recurring outflows available throughout the next 12 months after the proposed premium. Training labels are generated by this repository's simulator. Evaluation measures how well the model learns that simulator; it does not show performance on Zenith customers or validate insurance affordability.

Catalogue retrieval uses local TF-IDF text matching against the selected customer interests and product descriptions. The financial model assesses premium sustainability separately. This is a lightweight retrieval step, not a generative RAG system. The final explanation is assembled from the scored fields with fixed templates; an LLM is not needed to make the result structured.
